# 拾贝语言能力规划

日期：2026-07-13

## 背景

拾贝接下来需要支持英文用户。这个能力不能只理解为“把界面翻译成英文”，而是要拆成两条互相独立的产品线：

1. 前端界面语言：用户在 App 设置里选择中文或英文，影响按钮、导航、提示、设置页等固定 UI 文案。
2. 后端生成语言：用户在生成偏好里选择中文或英文，影响知识点、题干、选项、解析等 AI 生成内容。

这两条线必须独立。界面语言不应该偷偷改变生成内容语言；生成内容语言也不应该决定 App UI 语言。

## 标准做法

iOS 前端本地化采用 Apple 标准路径：

- 使用 Xcode String Catalog 统一管理本地化字符串。
- 使用 `en` 和 `zh-Hans` 作为语言区域。
- SwiftUI 通过 `EnvironmentValues.locale` 控制界面渲染语言。
- 对固定 UI 文案做本地化；对用户内容、原文、章节标题、AI 生成题目保持内容本身语言。

参考资料：

- Apple Developer：Localizing and varying text with a string catalog
- Apple Developer：SwiftUI `locale` environment value
- Apple WWDC23：Discover String Catalogs
- Apple Developer：Previewing localizations

## 第一阶段：前端界面双语

目标：

- 用户可以在 V2 “我的”页设置界面语言。
- 选择中文后，固定 UI 文案显示中文。
- 选择英文后，主路径固定 UI 文案显示英文。
- 设置持久化，下次启动仍保持用户选择。
- 用户上传、生成、章节列表、通知、我的页等主路径不能因为语言切换产生布局问题。

范围内：

- V2 根视图注入语言偏好。
- V2 Profile 设置卡片新增“界面语言”入口。
- 语言选择 Sheet。
- 主路径固定文案迁移到 `Localizable.xcstrings`。
- 调整已有旧版 `AppStore.appLanguage` 能力与 V2 共用同一存储 key。

范围外：

- 不翻译用户上传的原文。
- 不翻译已生成的知识点、题目和解析。
- 不在本阶段实现后端生成语言偏好。
- 不增加机器翻译运行时服务。

## 第二阶段：后端生成语言偏好

目标：

- 用户可以选择“总是生成中文”或“总是生成英文”。
- 无论源内容是中文、英文还是混合语言，后端生成结果都遵守用户偏好。
- 生成语言偏好与界面语言分离。

建议后端字段：

- `preferred_output_language`: `zh-Hans | en`
- 存储层：设备/账号级 user preference。
- 请求层：生成任务创建时把偏好写入 generation job snapshot。
- Prompt 层：所有输出结构字段的自然语言内容遵守该偏好；来源引用和原文摘录保持原语言。
- 测试矩阵：中文源生成中文、中文源生成英文、英文源生成中文、英文源生成英文、混合源生成指定语言。

风险：

- 模型可能局部漏遵守语言偏好，需要在输出验收里检查题干、选项、解析语言。
- 专有名词、产品名、代码术语不应强制翻译。
- 原文引用和用户可查看的来源内容应保持原语言，否则会影响溯源可信度。

## 验收标准

前端阶段：

- V2 App 启动后能读取语言偏好。
- “我的”页能切换中文/英文。
- Tab、上传页、章节页、通知页、我的页主路径文案随语言变化。
- 章节标题、题目、原文不被前端语言设置改写。
- Xcode build 通过。

后端阶段：

- 生成任务可读取用户输出语言偏好。
- AI 生成内容语言稳定遵守偏好。
- 质量报告记录源语言、输出语言、模型遵守情况。
